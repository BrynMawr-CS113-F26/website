= 2. Top Down Approach

When designing a program, its a good idea to take a top-down approach. In a top down approach, we use the following steps:

1. Identify features of the program
2. Identify the verbs and nouns in the feature list
3. Sketch out major steps
4. Write the program skeleton
5. Implement and test functions one at a time

[discrete]
== 2.1 Identify Features of the Program

What features are necessary for our tic tac toe program?

Some ideas to consider:

1. What do we need to keep track of and how will we do it? (think: the game grid, the current state of the game, whose turn it is, etc)
2. What does each player need to do? (think: make a move based on the current state of the board)
3. What is the flow of the program? (think: player 1 goes, game grid updates, player 2 goes, game grid updates...)
4. What do we need to check on each turn? (think: is this move legal? does this move cause the game to end?)
5. How will the players see the game grid?
6. When should the players see the game grid?
